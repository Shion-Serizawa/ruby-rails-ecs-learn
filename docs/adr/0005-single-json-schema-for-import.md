# ADR-0005: LLM 連携は JSON Schema 1ファイルを唯一の定義にする

- 状態: 採用
- 日付: 2026-11-05

## 背景

カンファレンスのタイムテーブルを手で入力するのは大変。LLM に整形させて取り込みたい。

## 決定

- アプリから LLM の API は呼ばない。ユーザーがプロンプトをコピーして LLM に渡し、出力された JSON を貼り付ける
- 取り込み形式は `app/schemas/conference_import.schema.json` の1ファイルだけで定義し、次のすべてで使う
  - 画面に表示する / コピーさせる / ダウンロードさせる (`/conference_import/schema.json`)
  - サーバ側の検証 (json_schemer)
- 検証は「JSON Schema → 日時の実在チェック → モデルのバリデーション」の段階で行い、エラーは JSON Pointer (`/talks/3/title`) で位置を示す
- 1件でも失敗したら何も保存しない

## 検討した他の案

| 案 | 採用しなかった理由 |
| --- | --- |
| アプリから LLM API を直接呼ぶ | API キーの管理と課金が発生する。使う LLM をユーザーが選べなくなる |
| スキーマを Ruby のコードで定義して JSON を生成 | 定義が2か所になる。JSON Schema のままのほうが LLM にも人にも読みやすい |
| CSV で取り込む | 入れ子 (カンファレンス → セッション → タグ) を表しにくい |

## 結果

- 良い: どの LLM でも使える。スキーマを変えれば、画面・検証・LLM への指示がすべて追従する
- 悪い: コピー&ペーストの手間が残る
- 注意: `Talk` の enum (status) を変えたらスキーマも直す。食い違うと spec が落ちる
